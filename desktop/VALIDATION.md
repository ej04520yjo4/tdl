# 桌面版交付驗證

日期：2026-10-13。版本：1.3.0。基底修訂：`70c561c0a6d44d8d7fffdea14988fc4104bc56d2`；前一版：1.2.0（`5b53dd4`）。

## 本版新增的測試範圍

- 進度節流：同一檔案的進度事件 250 毫秒內只放行一個，並以放行的樣本計算速度；結束後釋放紀錄。
- 進度寫檔：420 個連續進度事件的寫檔次數少於 20 次；工作中斷時最後的每檔狀態仍完整寫入；重開後可讀回。
- 佇列整理：已完成的工作只留檔案數與總大小，佇列檔於下次啟動移除該項目；失敗的項目保留到按「清除已結束」，可自動接續的項目不受影響；過期且無工作使用的掃描清單會清除。
- 進階下載設定：副檔名與檔名格式的正規化與拒絕條件（路徑字元、換行、同時設定「只下載」與「排除」）；設定值轉成核心旗標；預設值不產生多餘旗標；暫停的工作在設定變更後仍以原設定接續。
- 上傳／轉傳／備份／還原：目的地只接受清單參照、數字 ID 或 `@username`，運算式一律拒絕；說明文字會跳脫 HTML 並加引號；含逗號的路徑不會被拆成兩個；各選項對應的核心旗標；`whoami` 回報身分後才標記為已登入，沒有回報則不登入。
- 核心的環境變數隔離：繼承來的 `TDL_*` 不會傳給核心，本程式的 `TDL_DESKTOP_*` 保留。
- 介面：一個進度事件只更新自己的檔案列；有掃描總量時顯示整體進度、速度與剩餘時間，暫停後不再顯示速度；沒有總量的連結工作不顯示整體進度列；清除已結束；進階設定先驗證再儲存；上傳後刪除需要再次確認；試跑與正式轉傳的結果分開顯示；未登入帳號不能開始；Telegram 拒絕的備份不會留下帳號。
- Go：上傳失敗必須以失敗回報且不刪除本機檔案，取消不算失敗，成功才刪除並回報完成；帶類型的對話參照解析。

1.2.0 的回歸範圍（佇列捲動、關閉重開、取消、話題篩選、登入、環境隔離、匯出筆數／大小一致）全部保留並通過。

## 離線、真實核心與真實帳號驗證的區別

**自動化 fixture（模擬核心）。** `desktop/tests/` 以 Python 子程序代替 Go 核心，驗證後端、佇列與各頁面的行為。這類測試不連線，也不代表真實 Telegram 的行為。

**真實核心、不連線。** `desktop/tests/test_core_contract.py` 使用編譯好的 `bin/tdl-core.exe`：
- 以後端實際組出的 12 組參數（登入、清單、話題、掃描、下載含全部進階選項、上傳、轉傳、備份、還原、whoami）加上 `--help` 執行，確認核心認得桌面版會傳的每一個旗標。未知旗標會使核心以錯誤結束，已另行確認這項檢查不是空過。
- 備份與還原只使用本機儲存，以真實核心完成一次來回，並確認 GUI 模式只輸出協定事件。

**最終 EXE、離線。** `desktop/verify_release.py` 在移除 Python、Go 的 PATH 下啟動獨立副本，驗證核心來自單檔內部、離線畫面與原生 Windows 視窗正常啟動關閉。`desktop/verify_restart_release.py` 以離線模擬核心分兩次啟動最終 EXE，驗證保存、重開、自動恢復、同一工作、原帳號及完成檔案不重寫。

**真實 Telegram、不使用帳號。** `desktop/verify_qr_release.py` 以最終 EXE 向 Telegram 取得並顯示登入 QR Code，掃碼前取消；使用臨時資料夾，不讀取任何已登入帳號。

**真實 Telegram、使用已登入帳號的隔離副本。** `desktop/verify_channel_ui_release.py`（更新清單、選取話題）與 `desktop/verify_channel_release.py`（掃描並下載一個公開小型影片）。

## 開發過程中由測試發現並修正的問題

- 上傳與轉傳頁的進度清單原本把清除方法命名為 `reset`，覆寫了 Qt 的同名虛擬函式，`clear()` 會遞迴呼叫自己。介面測試當場失敗；已改名並保留說明。
- 樣式表的三角形箭頭寫法在 Qt 不成立（畫出小方塊），離線截圖檢視時發現；改用隨程式附帶的小圖檔，並在最終 EXE 的截圖確認有載入。

## 已知限制

- **上傳、轉傳未以真實 Telegram 驗證。** 這兩項會用帳號實際送出訊息，本版只以模擬核心、真實核心的旗標檢查與 Go 單元測試驗證。核心的傳送邏輯沿用原版 tdl，本版改動的是進度事件、錯誤回報與參數傳遞。第一次使用請先送到「儲存的訊息」，轉傳請先試跑。
- **備份還原的真實登入確認（`whoami`）未以真實帳號驗證**；備份與還原本身已用真實核心離線完成來回。
- **進階下載設定**的旗標已由真實核心確認存在，各選項的實際下載效果（例如 Takeout、檔名格式）未逐一以真實下載驗證。
- 完成附件可略過；未完成的單一檔案可能從頭重抓，不宣稱位元組續傳。
- 私人權限、已刪除訊息、磁碟空間、網路及大檔長時間下載依實際情況而定。
- 原始專案完整 Go suite 有既有 Windows `app/update/TestBinaryName`：預期 `tdl`、實際 `tdl.exe` 不一致。本次不宣稱原始專案全套通過。
- EXE 是未簽章的 Windows x64 GUI 程式，首次開啟需解壓內含元件。
