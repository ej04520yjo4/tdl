### 套件升級（第 3 項）

`govulncheck` 升級前回報程式實際呼叫到的 3 個漏洞：gotd 的 `proto.UnencryptedMessage.Decode` 記憶體無上限配置（GO-2026-6138）、klauspost/compress 的 zstd panic（GO-2026-6865）、Go 標準函式庫 `crypto/x509`（GO-2026-6809，需 Go 1.27.3）；另有 x/net、x/crypto、otel 的未呼叫漏洞。

- Go：gotd `v0.140.0 → v0.163.0`、klauspost/compress `v1.19.2 → v1.20.4`、x/net `v0.58.0 → v0.62.0`、x/crypto `v0.55.0 → v0.58.0`、otel `v1.41.0 → v1.47.0`、andybalholm/brotli `v1.2.7`（新版 gotd 帶進的 v1.2.1 有漏洞 GO-2026-6888）。gotd 新版要求 `go 1.26.0`；`go.work` 與三個 `go.mod` 加上 `toolchain go1.27.3`，舊工具鏈會自動切換。
- gotd 改用自己的記錄介面 `github.com/gotd/log`：`core/tclient/tclient.go` 以 `logzap.New` 轉接原本的 zap 記錄器，記錄內容不變。
- 升級後 `govulncheck`：程式實際呼叫到的漏洞 **0**。剩下 x/crypto 已停止維護的 `openpgp` 套件（GO-2026-5932），本專案未使用，官方也還沒有正式版修補。
- 桌面：PySide6-Essentials／shiboken6 `6.10.2 → 6.12.0`、PyInstaller `6.19.0 → 6.22.3`、pyinstaller-hooks-contrib `2026.8 → 2026.10`、pytest `9.0.2 → 9.2.0`、pluggy `1.7.0`、setuptools `84.2.1`。

## 已知限制

- CI 只跑測試，不建置 EXE、不做真實 Telegram 驗證。
- gotd 跨 23 個版本升級；自動化測試與真實帳號下載驗證之外的功能（上傳、轉傳實際送出、QR 登入）沒有用真實帳號實際操作。
- 續傳以 1 MB 分段為單位，失敗或暫停當下正在傳輸的分段會重抓；強制結束、斷電或命令列 Ctrl+C 仍從頭下載。
- EXE 未簽章；上游完整 Go suite 的 Windows `app/update/TestBinaryName` 已知差異未處理。
