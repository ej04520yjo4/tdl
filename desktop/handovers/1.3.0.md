## 檢閱結論：1.2.0 的主要問題

1. **進度紀錄拖慢下載本身。** 核心每寫入 1 MiB 就送出一個進度事件；後端每收到一個事件就把 `queue.json` 與 `downloads.json` 整份讀出、改寫、`fsync` 各一次，而且檔案越多、每次寫得越大。寫檔跟不上時，核心會卡在輸出管線上，等於下載速度被紀錄速度限制。以離線模擬核心實測 1000 個檔案、5000 個事件：1.2.0 需要 137.26 秒（每秒 36 個事件），1.3.0 為 0.42 秒（每秒約 11,800 個）。
2. **佇列畫面每個事件重掃全部檔案。** 每個事件都對所有檔案列更新一次，其中判斷新檔案是線性搜尋，檔案數多時成本以平方成長。
3. **上游上傳器把失敗當成功。** `core/uploader` 在單檔上傳失敗時仍以「無錯誤」通知完成；搭配 `--rm` 會刪除沒有成功送出的本機檔案。原版 tdl 也有這個問題，1.2.0 已修正下載器的同類問題，上傳器尚未處理。
4. **佇列與紀錄只增不減。** 已完成工作的每檔進度永久留在兩份 JSON；失敗、已取消的項目每次開啟都會回到佇列，沒有清除的方法；掃描產生的清單檔與工作副本不會刪除。
5. **版本號寫在八個地方**，更新時容易漏改。
6. 介面細節：下拉選單沒有箭頭、數字欄的上下鍵顯示異常、佇列只有一列時浮在中間、狀態標籤被拉長、頻道工作第二行顯示內部清單檔路徑、紀錄時間是 UTC 原始字串、每次開啟都要重新更新頻道清單、掃描只顯示數量不顯示大小。

## 修改與新增

### 效能與穩定

- `pkg/desktopio/throttle.go`：同一個檔案的進度事件最少間隔 250 毫秒；狀態變更（等待、完成、失敗）不受限。下載、上傳、轉傳共用。
- `desktop/backend.py`：進度先留在記憶體，最多每 2 秒寫檔一次，單檔失敗與工作結束時立即寫入。續傳由核心自己的檢查點與「略過相同檔案」決定，不依賴這些顯示用的紀錄。
- `desktop/app.py`：佇列列改為只更新有變化的那個檔案，總數以累計方式維護。
- 已完成的工作不再保留每檔進度，只留檔案數與總大小；佇列檔在下次啟動時移除已完成項目；超過 7 天且沒有工作使用的掃描清單會清除；工作結束時刪除其清單副本。
- 傳給核心的環境變數會先移除繼承來的 `TDL_*`（保留本程式自己的 `TDL_DESKTOP_*`），避免開發環境的設定影響核心。
- `core/uploader/uploader.go`：上傳失敗確實回報為失敗，`--rm` 只會刪除 Telegram 已收下的檔案；並等所有已啟動的工作結束再回傳。

### 新功能（對應原版 tdl）

| 原版指令 | 桌面版位置 | 說明 |
| --- | --- | --- |
| `dl --template / --include / --exclude / --desc / --takeout / --rewrite-ext`、`--threads`、`--delay` | 設定與說明 → 進階下載設定 | 每個工作記住建立時的設定，續傳不受之後的設定變更影響 |
| `up` | 上傳與轉傳 → 上傳檔案 | 檔案或資料夾、目的地、論壇主題、說明文字、以相片送出、排除副檔名、上傳後刪除 |
| `forward` | 上傳與轉傳 → 轉傳訊息 | 連結或 JSON、直接轉傳／複製、靜音、不帶相簿、由新到舊、試跑 |
| `backup` / `recover` | 帳號管理 → 備份／從備份還原 | 還原後以新增的 `whoami` 向 Telegram 確認登入有效才加入 |
| `chat ls` | 頻道下載 | 清單以 DPAPI 加密快取，下次開啟直接顯示；也供上傳／轉傳選目的地 |

其他：佇列顯示整體進度、大小、速度與剩餘時間；「清除已結束」；掃描後顯示總大小並在磁碟空間不足時提醒；日期捷徑新增近 90 日與全部時間；下載紀錄顯示本地時間與完成的檔案數、大小。

## 使用與維護交接

1. 關閉舊視窗後，雙擊根目錄 `TDL下載助手.exe`。帳號、設定與未完成工作沿用 `%LOCALAPPDATA%\TDLDesktop`，不需要重新登入。
2. 上傳與轉傳第一次使用時，建議先送到「儲存的訊息」；轉傳可先按「先試跑」。
3. 換電腦前在「帳號管理」按「備份」。備份檔沒有加密，請妥善保存。
4. 下次修改：改 `desktop/version.py` 的版本號，新增同名的 `desktop/handovers/<版本>.md`，執行 `desktop/build.ps1`，再依 `AGENTS.md` 完成驗證與同步。

## 已知限制與未做的部分

- 上傳與轉傳沒有續傳：關閉程式會中止（關閉前會詢問），已送出的不會收回，未送出的要重新開始。
- 佇列仍為每個檔案保留一列（1.2.0 的需求）。上千個檔案時更新已不再變慢，但清單很長；若想改成只顯示進行中與最近完成的檔案，需要另外決定。
- 原版功能尚未有介面的部分：`chat export` 的依訊息編號範圍／最近 N 則／留言串、`chat users`（匯出成員）、`dl --serve`、從 Telegram Desktop 匯入登入、`forward --edit` 與運算式路由、擴充套件。
- Windows DPAPI 無法使用時，登入資料會以未加密的封裝保存且畫面不會提示（1.2.0 既有行為，本版未更動）。
- 核心只在程序結束時寫入續傳檢查點；被強制終止時靠「略過相同檔案」補救（1.2.0 既有行為）。
- 原始專案完整 Go suite 的既有 Windows `app/update/TestBinaryName` 差異仍在，不宣稱全套 Go suite 通過。
- EXE 未簽章。
