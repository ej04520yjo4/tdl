# 1.6.0 交接清冊

日期：2026-10-31。基底：`master` 的 `27aa077`。功能分支：`codex/group-batch-forward`。

## 需求

直接選來源群組或子話題、日期範圍和檔案類型，再選目的群組批次轉傳，不必逐則貼連結。同步交付 Windows EXE、交接文件及 GitHub 更新。

## 操作流程

1. 開啟「上傳與轉傳 → 群組批次轉傳」，更新清單並選來源群組。
2. 論壇群組須選取來源話題；選日期及影片／照片／音訊／文件。日期為台灣時間，包含起迄日整天。
3. 選取自己的目的群組，若為論壇再選目的話題；掃描並確認符合條件的檔案數量。
4. 可先試跑；正式轉傳前確認來源、日期、檔案數量與目的地，再送出。

## 修改與相容性

- 保留原本的逐則連結／JSON 轉傳、本機檔案上傳、群組下載、儲存位置記憶與下載重開接續。
- 批次流程使用掃描產生的清單，強制只轉清單內訊息，不自動帶出篩選外的相簿內容。
- 發送前核對來源帳號、群組、清單雜湊及數量，工作使用獨立快照，避免排隊時清單被替換。
- 忙碌期間互鎖上傳／轉傳操作與帳號切換；取消不會撤回已送出的訊息。
- 此次更新不使用真實使用者帳號進行傳送驗證。

## 已知限制與設計選擇

- 沒有以真實 Telegram 帳號發送驗證。讀取／發送權限、受保護內容、刪除訊息、遠端限流與實際論壇行為仍需使用者在自己的群組驗收；建議先少量試跑，再確認送出。
- 只處理符合掃描條件的媒體及附帶說明，不搬移成員、純文字聊天或管理權限，原始訊息保留。強制 single，不保證保留原相簿編組。
- 正式轉傳一經確認嘗試，就消耗當次預覽；即使後端啟動前驗證失敗，也保守要求重掃。試跑失敗仍可修正後再試跑。
- 取消／失敗可能部分送達。沒有自動撤回、轉傳重開自動接續或跨工作去重，再次送出前需檢查目的群組。原有下載接續功能保留。
- EXE 未簽章；上游完整 Go suite 的 Windows `app/update/TestBinaryName` 已知差異未在此次處理。
