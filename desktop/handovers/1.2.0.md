# 1.2.0 交接清冊

日期：2026-10-13。使用者指定專案：`ej04520yjo4/tdl`。

## 本次需求

- 下載佇列可上下捲動，進度更新不能造成畫面反覆跳動。

## 修改與維護位置

- `desktop/app.py`：下載佇列、每個檔案的獨立進度、工作先保存再執行、啟動恢復及正常關閉。
- `desktop/backend.py`：原子寫入工作狀態、暫停與取消區分、來源清單保存、話題查詢與掃描參數。
- `desktop/channel_page.py`：帳號、群組、話題、日期及媒體篩選操作。
- `app/chat`、`cmd/chat.go`：Telegram 話題清單與限定話題的匯出。
- `app/dl/progress.go`、`pkg/desktopio`：穩定檔案識別與各檔案完成事件。
- `core/downloader/downloader.go`：單檔錯誤傳遞，以及取消時等待已啟動工作完成清理。
- `desktop/tests/`：佇列捲動、關閉重開、取消、話題篩選及既有登入／下載回歸。
- `desktop/build.ps1`、`desktop/package_release.py`：核心、測試、單檔 EXE、授權及來源 ZIP。

## 延續的既有功能

本次首次同步至 GitHub 的桌面版來源包含先前本機 1.0.x／1.1.x 工作：繁中視窗、QR／手機登入、DPAPI 帳號記憶、頻道列表、台灣日期範圍、媒體篩選，以及 1.1.1 的 Qt 背景執行緒修正。

## 續下載界線

保存的是原帳號、來源清單、輸出資料夾、工作參數與核心的已完成檔案紀錄。完成的附件會略過；正在下載而尚未完成的單一檔案，可能從頭重抓，不宣稱位元組續傳。手動取消及失敗項目保留可供重試，不自動重新下載。帳號權限遭撤銷、來源訊息刪除或輸出磁碟不可用時，需要處理原因後重試。

## 使用與維護交接

1. 關閉舊視窗後，雙擊根目錄 `TDL下載助手.exe`。帳號及資料沿用 `%LOCALAPPDATA%\TDLDesktop`。
2. 「頻道下載」→「更新清單」→ 選群組 → 選話題 → 選日期及類型 → 掃描 → 開始下載。未選話題時不能掃描論壇；只有明確選「全部主題」才包含整個群組。
3. 「下載中心」的下載佇列可用右側捲軸或滑鼠滾輪操作。每個檔案各自一列，完成及進行中狀態保留。
4. 正常關閉會先保存工作；重開自動使用原帳號接續。手動取消及失敗項目按「重試」才繼續。
5. 下次修改先依 `AGENTS.md` 新增交接清冊；執行 `desktop/build.ps1`，再以最終 EXE 跑需連線的明確驗證。重新核對收據雜湊後同步分支、PR 與 Release。

## 一併修正的續下載問題

- 單檔下載錯誤曾被核心吞掉、以成功傳入 OnDone；現在錯誤會被保存並顯示，未完成檔案不會進入完成 checkpoint。
- 取消時 iterator 可能先回傳錯誤；現在等候所有已啟動 worker 執行 OnDone，再保存 checkpoint。
- 檔案時間先套用到暫存檔，成功後才更名，避免後處理失敗留下看似完成的正式檔。
- 暫停標記保留在工作模型，不依賴已清理的 worker 映射；主題串流不會重建其他操作的頻道清單。

## 未擴大的驗證範圍

論壇實測只讀取清單並選取話題；沒有批次下載私人附件。話題範圍的 General／其他話題分流以核心回歸與 Telegram API 語意驗證。真實下載使用公開小型影片；離線恢復測試與真實 Telegram 下載驗證分開記錄。

原始專案完整 Go suite 的既有 Windows `app/update/TestBinaryName` 預期 `tdl`／實際 `tdl.exe` 差異仍保留，不宣稱全套 Go suite 通過。
